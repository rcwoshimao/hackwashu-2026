# Ground Control build plan

This plan follows `docs/CODEX_MASTER_PROMPT.md` and the user's later instructions to finish the product, focus on iMessage, and keep ordinary public scans free of code execution. Azure App Service hosts the public server; Docker Desktop remains a local run path. The public scanner always remains static and optional AI. A private connected repository, or a public repository owned by the signed-in user and explicitly opted in, may run deep checks in its own CI or an owner-approved local checkout.

- Assumptions: the starter kit copied from `files/ground-control-starter/ground-control-starter/` is the project source; the supplied master prompt governs conflicts. Phase 1 implements `file_exists`, `script_exists`, `code_reference`, `env_var`, and `version`; `cli_flag` joins the other three remaining kinds in Phase 2. Generalized schema fields absent from the spec are kept minimal and recorded in an ADR before public types freeze. No project code runs in static checks.
