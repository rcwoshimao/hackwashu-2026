# Human setup for the local Ground Control demo

Ground Control runs locally with Docker Desktop. Add keys to the ignored `.env` file in this repository; never put a credential in Git, a README, an issue, or a screenshot. You can run the web app and the bundled Orbit drift fixture before creating any account. Ordinary public scans use static and optional AI checks without executing repository code. A private repo you connect or a public repo owned by your signed-in GitHub account can use deep checks after explicit Actions setup.

| # | Action only you can take | Put the value here | Verify it |
| --- | --- | --- | --- |
| 1 | Start Docker Desktop. Install Bun and Node.js only if you want to run development commands directly on the host. | Local machine | `docker compose up --build -d` starts a healthy `groundcontrol` container; `docker compose exec -T groundcontrol bun ops fly` runs the keyless drift rehearsal. |
| 2 | Edit `GROUND_CONTROL_PORT` in `.env` if 8787 is occupied. This workspace's local `.env` uses 8877. Set `PUBLIC_URL` only if you use an HTTPS tunnel or another browser origin. | `.env` | Open the configured URL and check `/healthz` returns `ok`. |
| 3 | Create a read-only GitHub token for public repository API requests. | `.env`: `GITHUB_SCAN_TOKEN` | Run `docker compose exec groundcontrol bun ops sky:scan --top 20 --tiers static` and see real, SHA-labeled satellites. |
| 4 | Create a Gemini API key in Google AI Studio. | `.env`: `GEMINI_API_KEY` | Recreate the container, then run the 20-repo scan with `--tiers static,ai`; the satellites report both tiers. Source text is sent to Gemini for this tier. |
| 5 | Create a GitHub OAuth app. Set its callback to `<PUBLIC_URL>/auth/github/callback`. Generate a long random session signing value in a password manager. | `.env`: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `SESSION_SECRET` | Sign in from the web app, return to **My repos**, and see your GitHub login in the header and account view. Your accessible repositories load automatically. For a local callback, use the exact localhost origin you open. |
| 6 | If testing connected repo write actions or iMessage drift alerts, create a short-lived fine-grained GitHub token scoped to your demo repository. Grant **Contents: read and write**, **Pull requests: read and write**, and **Commit statuses: read and write**. | `.env`: `GITHUB_WRITE_TOKEN` | A connected repo's telemetry produces a `Ground Control` commit status and the server can verify the commit author before addressing an iMessage. Limit this token to the test repo. |
| 7 | On **My repos**, choose **Connect** on a private repo or **Enable deep checks** on a public repo owned by your signed-in account. Copy the one-time telemetry token before leaving the page. An ordinary public **Connect** remains documentation-only. | That repo's Actions secret `GROUND_CONTROL_TOKEN` | Enabling deep checks issues a scoped token. Repeating the enable action rotates it, so update the Actions secret. |
| 8 | Generate the first flight checks **before enabling the Action**: from this repo's root run `bun ops seed-plan <checkout> <owner/repo>` against a checkout you own, then review and commit the three generated `flightchecks/` files there. | The connected repo's default branch | After explicitly running `npm ci`, `node --test flightchecks` passes in that checkout. These commands execute its code. With `GITHUB_WRITE_TOKEN` and Contents write access, changed sources in an opted-in repo may publish a new plan after the writer rechecks visibility; verify its commit, or rerun `seed-plan` manually. |
| 9 | Publish this repository's `action/action.yml` and `action/dist/index.js` to a GitHub repo the runner can fetch. Copy `demo/orbit-app/.github/workflows/ground-control.yml` into the opted-in repo and replace `YOUR_GITHUB_USER/ground-control/action@main`. | That repo's workflow; Actions variable `GROUND_CONTROL_URL=<PUBLIC_URL>` | A same-repo push produces a run. The flight-checks job has no telemetry secret, skips fork PRs, and checks repository identity before importing the runner; the report job sends telemetry. |
| 10 | Before a GitHub-hosted run, keep an HTTPS tunnel to the Docker host port running. Set `PUBLIC_URL` to its origin, update the OAuth callback and `GROUND_CONTROL_URL`, and recreate the container. | `.env`, GitHub OAuth app, Actions variable | `https://<your-tunnel>/healthz` returns `ok`. GitHub-hosted runners cannot reach your `localhost`. Spectrum Cloud iMessage connects outbound and does not need this tunnel. |
| 11 | Run `bun run build:extension` with the final `PUBLIC_URL` or local `GROUND_CONTROL_PORT`, load `apps/extension/dist` unpacked in Chrome, and copy its assigned ID. | `.env`: `EXTENSION_ID` | Recreate the container; extension sign-in returns to that ID. When `PUBLIC_URL` is blank, the extension build uses this workspace's local port 8877. |
| 12 | If testing iMessage, create a Photon Spectrum project and provision a cloud iMessage line. | `.env`: `SPECTRUM_PROJECT_ID`, `SPECTRUM_PROJECT_SECRET` | Recreate the container. On the signed-in Connect page, enter your iMessage phone in `+` international format and choose **Send linking message**. Reply with the `LINK <code>` line received in Messages. A welcome reply confirms the link; confirmed drift can then produce one grouped alert. No Mac is required for Spectrum Cloud. |
| 13 | If testing Confluence, create a test Cloud site and API token, then add a page link for a connected repo. | `.env`: `CONFLUENCE_SITE`, `CONFLUENCE_EMAIL`, `CONFLUENCE_API_TOKEN` | The Add source page shows fresh or error status and lets an admin refresh it. Corrections post footer comments; the page body is never edited. |

Run `docker compose up -d` after changing `.env` so the container receives the new values. The normal Sky starts empty until you scan real repositories or sign in to see your account's unscanned holding-orbit marks. The 500-repo scan is an explicit command because it consumes GitHub and Gemini quota; start with 20 to verify keys.

To reuse Rebecca's measured public scan data in this local Docker database, run `docker compose exec -T groundcontrol bun ops sky:load snapshots/sky-snapshot.json`. The loader skips private records and keeps newer local scans and existing connections.

To check repositories from your signed-in account, open `http://localhost:<GROUND_CONTROL_PORT>/signin` and use the **My repos** list. **Check README** requests a static and optional AI check for one public repo. **Scan all public READMEs** requests those checks for eligible public repos in the displayed list; it does not include private repos. Listing your repositories does not connect or scan them. GitHub returns up to 500 recently updated accessible repos in this view; the page says when more exist. After an image rebuild, sign in again if `SESSION_SECRET` was left blank, because the generated signing secret changes when the server restarts. Set a stable `SESSION_SECRET` to keep the session across restarts.

The signed-in Sky also shows your unscanned repos as neutral holding-orbit marks, separate from measured public scan positions. Saved private CI results show their real status while remaining in that orbit, whose position does not represent lag or stars. Choose **My repos** to see repositories in your GitHub account inventory, or **All public repos** to see measured public repositories outside that inventory. Search and paging work in either view. The Canvas shows every repository matching the active filters; the list below it is paged for easier selection. Select a repo on the map or in the **Repositories** list, then choose **Review findings** for a plain-language result. Dot size indicates GitHub stars, within the space available in dense groups. A hollow dot labeled **No verified checks** means a scan had no checkable claims, or a connected repo has no check results yet; it does not mean the scan failed. The repository page keeps source sync fields and run history under expandable details. The account avatar links to your full inventory and **My reports**; your login is visible beside it on desktop. An eligible public repo you own also shows **Enable deep checks**, which opens a prefilled connection form. Ordinary public scans inspect docs and metadata only. Demo satellites are hidden from the normal Sky; `/api/sky?demo=1` shows them only when no real scans exist.

Optional Claude extraction: add `ANTHROPIC_API_KEY` and `EXTRACTION_MODEL=claude` to the ignored `.env` before starting the server or an owner-selected local scan. Gemini remains the public Sky AI provider. From this workspace, `bun run gc scan --owned <checkout>` initializes and runs checks in a checkout you own, and `bun run gc check --owned <checkout>` reruns them without requiring a Git repository. Review its generated plan and runtime commands first. The earlier `--private` flag remains supported. This is a local script, not a published `npx` package.

Report mode rejects telemetry when its repository, commit SHA, or PR number differs from GitHub's workflow context. The check results are produced in the connected repository's CI checkout, so keep the Ground Control status advisory for branches whose authors can edit the generated runner until trusted attestation is added. A documentation change on the default branch queues immediate source refresh; PR branch documentation needs a manual refresh or a reviewed `seed-plan` commit before relying on new checks.

The sample workflow reports same-repo PRs only; fork PRs are skipped even if GitHub is configured to pass secrets to forks. A missing `GROUND_CONTROL_URL` or `GROUND_CONTROL_TOKEN` fails a same-repo report job. The server needs `GITHUB_WRITE_TOKEN` to look up the actual commit's GitHub author before sending iMessage. Without it, telemetry remains stored, but status, PR comment, and alert delivery are unavailable. If GitHub cannot identify a linked author, the stored run and available PR comment remain, but no alert goes to the PR opener or a name supplied in telemetry.

For a keyless local drift rehearsal, run `docker compose exec -T groundcontrol bun ops fly` after starting the container. It copies Ground Control's bundled `demo/orbit-app` fixture to a disposable checkout, runs its checks, applies the port change, and leaves the original fixture untouched. It never fetches a public repository. For a host fallback, install Bun and Node.js, run `bun install` in this repository, and run `npm ci` in `demo/orbit-app` if its `node_modules` directory is absent. Then run `bun ops fly` from this repository's root. See [SELF_HOST.md](SELF_HOST.md) for the full local procedure.

Check each configured external service before the audience arrives: `docker compose exec groundcontrol bun ops ping-github` for GitHub and `docker compose exec groundcontrol bun ops ping-models` for Gemini. The first requires a scan or write token; the second requires `GEMINI_API_KEY`. Neither command needs to print a credential.

To record the optional DIY comparison, set `GEMINI_API_KEY` on the host, ensure Docker has the `node:24` image (`docker pull node:24`), and run `bun ops benchmark-diy demo/orbit-app --runs 10` from this repository. If `demo/orbit-app/node_modules` is absent, run `npm ci` in that fixture first. The command writes measured results to `evals/diy-vs-ground-control.md`; without the key, the report remains explicitly unmeasured.
